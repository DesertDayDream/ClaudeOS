# ClaudeOS desktop

The Electron shell owns desktop integration. The existing Node backend runs as a
separate process so agent sessions and native terminal modules do not depend on
Electron's Node ABI. User data remains in `CLAUDEOS_HOME` (default `~/.claudeos`).

## Development

Use Node 24 on Windows x64. From the repo root:

For dependency installation, automated checks, real Electron and packaged-app
smoke tests, and installer creation in one command, run `npm run desktop:finish`
from a normal PowerShell terminal. The command leaves the live app running,
uses temporary lab data, and writes its progress to `.devdata/desktop-finish.json`.
It stops at the first failure and prints the installer path only after both real
smoke tests pass. Installation, public release, and real sign-in/update validation
remain separate steps.

```powershell
npm ci
npm run desktop:setup
npm run test:desktop
npm run test:desktop-backend
```

`desktop:setup` installs the pinned desktop dependencies separately from the
backend. Commit the generated `desktop/package-lock.json` before a release;
subsequent clean installs should use `npm --prefix desktop ci`.

Run a lab instance with its own data and account configuration:

```powershell
$labDir = Join-Path $env:TEMP ('ClaudeOS-Desktop-' + [guid]::NewGuid())
$env:CLAUDEOS_HOME = Join-Path $labDir 'data'
$env:CLAUDE_CONFIG_DIR = Join-Path $labDir 'claude'
$env:CODEX_HOME = Join-Path $labDir 'codex'
$env:PORT = '4800'
$env:ARTIFACT_PORT = '4810'
npm run desktop
```

The backend integration test creates its own lab copy in `%TEMP%`, uses port
4800, and simulates unavailable account CLIs. It tests HTTP and desktop IPC;
it does not test real account sign-in, terminals, or Electron rendering.
The shell tests use mocked Electron APIs and verify isolation, navigation,
permissions, notifications, window lifecycle, and update shutdown ordering.

`npm run test:codex` verifies App Server approvals, resume, cancellation, and
fail-closed responses. `node scripts/test-codex-live.mjs` uses the signed-in
Codex account for a harmless real approval test in a temporary folder, followed
by a read-only resume. Only the expected marker-writing command is approved.
Codex uses ordinary Windows shell executables instead of Store aliases in its
child environment; the user's global PATH and sandbox settings are unchanged.

## Packaging and verification

`npm run build:desktop` builds an NSIS installer in `dist/desktop/`. It packages
the Node backend separately and leaves the live legacy `dist/ClaudeOS.exe`
untouched. `npm run build:desktop -- --dir` creates an unpacked app for QA.
Only Windows x64 packaging is implemented in this first version.

Set `CLAUDEOS_DESKTOP_SMOKE` to an absolute JSON output path, retaining the lab
environment above, and launch the development or packaged app. The smoke check
verifies the renderer sandbox, settings connection, real terminal command
completion, and closing to the tray, writes the result, then quits.

Before installation, verify the packaged app visually, sign-in links and callbacks,
Claude/Codex replies, attachments, previews, microphone behavior, hotkey conflicts,
start with Windows, and a full installer update. Browser speech recognition may
differ in Electron and needs a real compatibility check.

The app log is `CLAUDEOS_HOME/desktop.log`; the packaged backend also writes
`CLAUDEOS_HOME/claudeos.log`. Closing the window hides it; Quit from the tray
stops the backend and its active sessions. A second launch restores the window.

## Releases

The installer includes a GitHub update feed for `DesertDayDream/ClaudeOS`.
Building never publishes a release. A release must include the installer,
its blockmap, and `latest.yml` generated by electron-builder. Check for updates
is manual; downloads require confirmation, and installation waits for agent
turns to finish. Rollback uses a previous installer and preserves user data.

Configure a Windows signing certificate in the release environment before public
distribution. Without one, Windows treats the installer as unsigned. Keep signing
credentials out of the repository. The first live installer/update and signing
have not been verified in this implementation environment.
